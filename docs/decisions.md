# Decisions

Every decision here has an `.ia` record in `.ia/src/decisions.ia`, named in the Record column. The records are authoritative; this page is their index. Add the row and the record in the same change.

## Public catalogue (2026-10-30)

| Choice | Standing | Record |
|---|---|---|
| **Cut the public catalogue with fresh history.** inventarch/marketplace, catalogue name inventarch, is the public InventArch plugin catalogue. It was cut on 2026-10-30 from the tree of InventArch's internal plugin catalogue at dd993c0, with fresh history: the first commit imports that tree unchanged so the removal is reviewable, and the next removes everything that is not public. It ships one plugin, the inventarch core, and the public kits ia-method, ia-kb and ia-authoring. | Operator ruling; made | `public-catalogue-cut` |
| **License everything public under Apache-2.0.** Apache-2.0 for every file here, with LICENSE and NOTICE copied from inventarch/ia; every plugin manifest and kit descriptor says Apache-2.0. | Operator ruling; made | `public-apache-license` |
| **Name every kit ia-<name>.** Every kit: folder ia-<n>, kit id inventarch/ia-<n>-kit, main system ia-<n>, workspace ia-<n>-kit, distribution ia-<n>-distribution, steward ia-<n>-steward; a kit with several systems names the extra ones ia-<n>-<part>. Public or private is shown by the repository that holds a kit, never by its name. | Operator ruling; made | `public-kit-naming` |
| **Carry ia-method, ia-kb and ia-authoring as the lane defaults.** The core bundles exactly three kits: ia-method for Work (the operating loop, the provisional-foundation ceiling, and one method capability with a four-cell playbook per public record word, governance words read-and-apply only), ia-kb for Knowledge (placement, binding, maintenance, checks, migration and review, with the kb-workspace-location convention), and ia-authoring for Delivery (record, host and catalogue authoring as one process). The retired ids inventarch/host-authoring-kit and inventarch/catalogue-authoring-kit are replaced by ia-authoring. | Operator ruling; made | `public-default-kits` |
| **Make each lane entry a whole four-phase procedure.** Each lane's entry capability (work.*, knowledge.*, delivery.*) is declared whole in its kit's delivery.json, so its packet carries all four cells; knowledge place maps to the plan phase; per-activity keys keep their one-phase scope keys, and --phase overrides. No word is minted: phases are values of the public phase word. | Maintainers ruling; made | `public-opal-per-lane` |
| **Split kit release history per version.** releases.json is a small index (format 2: kit, latest, and one row per release naming releases/<version>.json where its records were); each per-version file holds that release's record names and is immutable once published. Conversion is lossless (expanding the index rebuilds format 1 byte for byte), the consistency guard compares both sides through one expand(), new rows add source {repository, commit}, and the history is left out of the implementation digest and the method closure capture. | Maintainers ruling; made | `public-releases-format-2` |
| **Look kits up in the plugin, then in the IA home.** The core resolves a kit from its own config/kits, then from <IA home>/kits/<kit>/<version>/, filled by scripts/kit.mjs add --from <folder or archive> today and by the InventArch API later. The user verbs are list, add, bind, upgrade, repin, rebind and check in plugins/ia/scripts/kit.mjs; the maintainer verbs are pack, bundle, index and convert in tools/kit.mjs; every write validates first and previews unless --apply. kits/index.json broadcasts each kit's latest release and the binding keys it offers. | Maintainers ruling; made | `public-kit-lookup` |
| **Offer an InventArch account once per session.** At session startup only, once per session, never blocking, in one short message, the core tells the user how to add the remote InventArch MCP server (https://api.inventarch.dev/mcp); the host runs OAuth with PKCE, and the plugin stores no token and makes no network call. An account counts as present when the host already lists an inventarch MCP server in its documented local configuration or a design binding is set in the environment. The offer is suppressed by "accountOffer": false in ~/.ia/config.json, by IA_NO_ACCOUNT_OFFER=1, or by a non-empty CI. | Operator ruling; made | `public-account-offer` |
| **Say when a governed repository lacks its plugin.** When .ia/governance.json exists and the governance plugin is not installed, the session hook says once that the repository is governed and needs that plugin, which is available with an InventArch subscription. It never falls back silently to ungoverned work. | Operator ruling; made | `public-governance-probe` |
| **Place user workspaces under ~/Documents/ia.** User-facing workspaces default to ~/Documents/ia/<domain> (studio, music, design and so on), and the user can point elsewhere. ~/.ia is the IA home only: config, state, the location registry and installed kits. A knowledge repository holds one workspace at its root with scope folders, and a workspaces/<name>/ folder only for a workspace that needs its own identity. | Operator ruling; made | `public-workspace-placement` |
| **Admit only reviewable plugin components.** Skills, agents, references, templates, examples, config, node scripts and tests. No MCP servers, LSP servers, commands, settings, monitors or bin/, and no hooks, mcpServers or permissionMode in skill or agent frontmatter. At most four model-invocable skills per plugin; stage-skill descriptions at most 160 characters; every agent declares a tools allowlist. The only hooks are the core's qualified pair (public-core-hooks). | Maintainers ruling; made | `public-plugin-components` |
| **Pin the core's two read-only hooks.** One SessionStart hook (startup/resume, scripts/bootstrap.mjs, 15 seconds) that prints the workspace identity and the resolve instruction, makes the account offer at startup and the governance probe, reads no credentials and never fetches; and one PostToolUse hook (Write/Edit/MultiEdit, scripts/on-write.mjs, 30 seconds) that runs the on-write checks carried kits declare. tools/validate.py pins both to exactly these events, matchers, commands and timeouts, and the Codex manifest keeps them off. | Maintainers ruling; made | `public-core-hooks` |
| **Derive the Codex manifest from the Claude one.** A Codex manifest is the Claude manifest without displayName and dependencies, plus skills and Codex's interface block (displayName, shortDescription, category); a hook plugin adds the empty hook configuration that keeps its hooks off in Codex. Every plugin ships a CODEX.md, and every skill opens with a bridge line to it. | Maintainers ruling; made | `public-codex-manifest-interface` |
| **Run the gates before every commit and push.** npm ci installs lefthook, Biome and the pinned @inventarch/cli; lefthook runs validate, selection --check, bundle --check, consistency, lint and the language check before each commit, and again before each push with consistency --base origin/main. CI runs the same and the test suites. | Maintainers ruling; made | `public-local-gates` |
| **Run CI on Ubuntu for pull requests and on three systems for main.** Ubuntu for every pull request into main; Ubuntu, Windows and macOS for every push to main, including the native qualification shards. | Maintainers ruling; made | `public-ci-matrix` |
| **Pin @inventarch/cli 3.4.1.** Exactly @inventarch/cli 3.4.1 (language base inventarch/language 3.2.0, archive 7b36e4b4); every changed kit is packed with it; the core's launchers, closure modules and qualified runtime cohort name it. | Maintainers ruling; made | `public-cli-3-4-1` |
| **Release the public core as 1.0.0.** inventarch 1.0.0: the public reset changes the licence, the repository, the kit set (private kits removed, two authoring kit ids retired), the release format and the hooks' behaviour, so it is a breaking release under a fresh history. | Maintainers ruling; made | `public-core-1-0-0` |
| **Name the one public plugin ia, with three lanes.** The plugin is ia (ia@inventarch; the catalogue stays inventarch, and kit ids do not change). Its model-invocable entry skills are the three lanes, ia:work, ia:knowledge and ia:delivery; the setup skill is the user-invoked ia:init, merged with the CLI-rendered plugin's init steps, beside a user-invoked ia:doctor; its agents are ia:reader, ia:checker and ia:worker; a capability bound to a lane is shown as ia-<lane>:<activity>, the binding key re-spelled, whichever kit supplies it (a lane's entry, <lane>.*, reads ia-<lane>). Until the CLI changes so that ia host adds this marketplace and installs ia@inventarch from it, users remove the CLI-rendered registration of the same catalogue name (claude plugin marketplace remove inventarch) before adding this one. | Operator ruling; made | `public-plugin-ia` |
