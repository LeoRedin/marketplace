# Decisions

Every decision here has an `.ia` record in `.ia/src/decisions.ia`, named in the Record column. The records are authoritative; this page is their index. Add the row and the record in the same change.

## Public catalogue (2026-10-30)

| Choice | Standing | Record |
|---|---|---|

It was cut on 2026-10-30 from the tree of InventArch's internal plugin catalogue at dd993c0, with fresh history: the first commit imports that tree unchanged so the removal is reviewable, and the next removes everything that is not public. It ships one plugin, the inventarch core, and the public kits ia-method, ia-kb and ia-authoring. | Operator ruling; made | `public-catalogue-cut` |
| **License everything public under Apache-2.0.** Apache-2.0 for every file here, with LICENSE and NOTICE copied from inventarch/ia; every plugin manifest and kit descriptor says Apache-2.0. | Operator ruling; made | `public-apache-license` |

| **Carry ia-method, ia-kb and ia-authoring as the lane defaults.** The core bundles exactly three kits: ia-method for Work (the operating loop, the provisional-foundation ceiling, and one method capability with a four-cell playbook per public record word, governance words read-and-apply only), ia-kb for Knowledge (placement, binding, maintenance, checks, migration and review, with the kb-workspace-location convention), and ia-authoring for Delivery (record, host and catalogue authoring as one process). No word is minted: phases are values of the public phase word. | Maintainers ruling; made | `public-opal-per-lane` |

The user verbs are list, add, bind, upgrade, repin, rebind and check in plugins/ia/scripts/kit.mjs; the maintainer verbs are pack, bundle, index and convert in tools/kit.mjs; every write validates first and previews unless --apply. kits/index.json broadcasts each kit's latest release and the binding keys it offers. | Maintainers ruling; made | `public-kit-lookup` |
| **Offer an InventArch account once per session.** At session startup only, once per session, never blocking, in one short message, the core tells the user how to add the remote InventArch MCP server (https://api.inventarch.dev/mcp); the host runs OAuth with PKCE, and the plugin stores no token and makes no network call. An account counts as present when the host already lists an inventarch MCP server in its documented local configuration or a design binding is set in the environment. The offer is suppressed by "accountOffer": false in ~/.ia/config.json, by IA_NO_ACCOUNT_OFFER=1, or by a non-empty CI. | Operator ruling; made | `public-account-offer` |
| **Say when a governed repository lacks its governance kit.** When .ia/governance.json exists and no installed kit declares governance handlers (a tool pre handler in its handlers.json), the session hook says once, at startup, that the repository is governed and to add the ia-governance kit (ia kit add). No plugin is looked for. It never falls back silently to ungoverned work. | Operator ruling; made | `public-governance-probe` |

A knowledge repository holds one .ia/src: a personal or single-team KB has one `@workspace`; an organisation store has one `@workspace` per department, each declaring its scope folders, plus an organisation `@workspace` that also declares the repository root (. @authored); a workspaces/<name>/ folder is only for a workspace released or adopted on its own. | Operator ruling; made | `public-workspace-placement` |

At most four model-invocable skills per plugin; stage-skill descriptions at most 160 characters; every agent declares a tools allowlist. | **Derive the Codex manifest from the Claude one.** A Codex manifest is the Claude manifest without displayName and dependencies, plus skills and Codex's interface block (displayName, shortDescription, category); a hook plugin adds the empty hook configuration that keeps its hooks off in Codex. Every plugin ships a CODEX.md, and every skill opens with a bridge line to it. | Maintainers ruling; made | `public-codex-manifest-interface` |

| **Run CI on Ubuntu for pull requests and on three systems for main.** Ubuntu for every pull request into main; Ubuntu, Windows and macOS for every push to main, including the native qualification shards. | Maintainers ruling; made | `public-ci-matrix` |

## The IA door, kit handlers and kit dependencies (2026-10-30)

| Choice | Standing | Record |
|---|---|---|
| **Ship the IA door as the core's MCP server.** The core ships one MCP server, the IA door, as plugins/ia/.mcp.json: server ia, run as node scripts/door.mjs, a launcher that starts npx -y `@inventarch/mcp-door` at the plugin's IA pin (3.4.1, lib/cli.mjs PINNED) never through a shell (on Windows, where npx is a .cmd shim, it runs npm's npx-cli.js with node), with stdio passed through and IA_KITS_DIR set to the plugin's config/kits. Codex reads a plugin's .mcp.json too, so the Codex manifest keeps the door off with an empty mcpServers until it is qualified there. Claude Code names its tools `mcp__plugin_ia_ia__<tool>`, and the reader, checker and worker allowlists name ia_session, ia_catalogue and ia_method that way (reader and worker also ia_position, ia_read and ia_vocabulary). The lanes call ia_session once per session, ia_catalogue {lane} to choose a key and ia_method {key} for the packet; until `@inventarch/mcp-door` ships ia_method they fall back to scripts/resolve.mjs and kit.mjs list. tools/validate.py admits that one file, exactly. | Operator ruling; made | `public-door-mcp` |
| **Run the handlers installed kits declare.** A kit may ship handlers.json (format 1: session handlers with their events, prompt, tool with phase pre or post and a tool-name match, and stop, each a .mjs script inside the kit with a timeout of at most 25 seconds). scripts/handlers.mjs runs them from SessionStart (every source), UserPromptSubmit, PreToolUse and PostToolUse on edits and shell commands, and Stop, only for installed kits (this plugin's config/kits and <IA home>/kits) whose folder holds the script, so a fetched release, which carries no executables, never runs one. Each runs as node <script> with the hook JSON on stdin and IA_KIT_ROOT, IA_WORKSPACE_ROOT and IA_HOME set; the core merges their additionalContext at most 2,000 characters per kit; a pre block is honoured only in a workspace with .ia/governance.json; with no handler declared every hook is a silent no-op. onwrite.json runs as tool post handlers. handlers.json is a sidecar the sources digest covers, and its scripts must be declared assets. | Operator ruling; made | `public-kit-handlers` |
| **Vendor the kits a kit depends on.** A kit release's .ia/release.json dependencies other than inventarch/language name a kit id and range. Adoption (kit.mjs add), add --from and the restored read root resolve each dependency, transitively and dependencies first, from the kits this plugin carries, then <IA home>/kits, then the dependency's own folder next to the kit; the first whose latest release satisfies the range wins. Its sources must pack to that recorded release, and its archive goes with the language base into the copy's or the workspace's vendor catalog, so ia install --catalog and ia restore --catalog resolve it. A missing dependency, a cycle or two releases of one kit is refused before anything is written. | Operator ruling; made | `public-kit-dependencies` |
| **Delegate across models only on the person's word.** Only through the user-invoked ia:delegate (disable-model-invocation), off by default until the person sets delegation true in ~/.ia/config.json or IA_DELEGATION=1. scripts/delegate.mjs builds a codex exec or claude -p command that gets the IA door (--mcp-config for claude -p, -c mcp_servers.ia for codex exec) and the brief with the packet inline on stdin, sets IA_DELEGATION_DEPTH one higher, refuses when it is already 1 or more, applies a timeout (900 seconds by default, at most 3,600) and runs only with --run. | Operator ruling; made | `public-delegate` |

## Kit trust and process hygiene (2026-10-31)

| Choice | Standing | Record |
|---|---|---|
| **Trust kit code by publisher and recorded digest.** A kit may run code (a handlers.json run script, an onwrite.json command or a checks.json command) only when its publisher, the kit id's namespace, with which a .ia/release.json publisher field must agree, is on the plugin's config/trusted-publishers.json, which ships as inventarch alone, and its sources digest equals its latest release's recorded sources, with .ia/release.json naming that release; a handler's run script must also be a declared asset. Any other kit, and a kit with no recorded release, is data only: a handler entry may carry a context text, delivered as additionalContext with no process; its run entries and onwrite.json commands are skipped, its checks are refused with IA-CORE-KIT-UNTRUSTED, and the SessionStart answer names each such kit once, with why. A pre handler of a kit whose publisher is not on the list never blocks. In a governed workspace a trusted pre handler that fails, times out or answers past the output cap refuses the call, and an altered gate refuses every pre-tool call: while a kit whose id names a trusted publisher declares a pre handler whose code the trust check refuses (its bytes are not its recorded release, or its script is not a declared asset), each such call is refused, naming the kit and the fix, which is to reinstall its recorded release with node <ia plugin>/scripts/kit.mjs add --from <release> --apply or to remove .ia/governance.json. Nothing extends the list at run time. Every child the three runners start gets an allowlisted environment (never NODE_OPTIONS or NODE_PATH), its process tree is killed on its deadline, and a hook child keeps at most 256 KiB of stdout and of stderr: hygiene, not a sandbox. | Operator ruling; made | `public-kit-trust` |

## The public kits package (2026-10-31)

| Choice | Standing | Record |
|---|---|---|
| **Publish the bundled kits as `@inventarch/public-kits`.** `@inventarch/public-kits` carries the kits the core bundles as one npm package, generated in packages/public-kits/ by node tools/kit.mjs package from plugins/ia/config/kits and kits/index.json. Its committed package.json holds its own semver, raised whenever a carried release changes (consistency --base checks it), and ia.kits: each kit's id, latest version, IA archive and manifest sha256, sources digest and folder; it has no scripts, dependencies, entry points or exports. The built files, gitignored, are archives/<archive>.ia.tgz (each recorded release packed again with the pinned CLI, refused unless it is that release) with archives/<archive>.distribution.json (its manifest), kits/<folder>/ byte for byte, index.json, LICENSE and NOTICE; the kit folders stay because an archive carries no sidecars. package --check is a gate in lefthook, npm run check and the gates workflow. .github/workflows/publish-public-kits.yml, started only by workflow_dispatch from main, checks the package against its sources, refuses a version npm already has, builds it and runs npm publish --provenance --access public under OIDC trusted publishing with no token; running it is the operator's step. | Operator ruling; made | `public-kits-package` |
